# Host responsibilities / Responsabilités de l’hôte

## English

The exercised host is Codex on Windows with local PowerShell, CPython 3.14.3 and
NTFS files. The agent reads these project skills explicitly; they are portable
repository instructions, not proof of automatic discovery in another client.
The wheel provides deterministic `capture`, `reconcile`, `verify` and `handoff`
commands. The repository provides the paired templates and walkthrough assets.

The operator/host chooses permitted files, actually saves drafts, checks paper
transcription and confirms task scope. Confirmation flags record those assertions;
they are not authentication, permission enforcement or evidence that software read
the paper. OS file permissions and the host's access boundaries still apply.
Only selected local read authority is represented; no account credentials are
needed. A skill cannot provide storage, credentials, role enforcement or reliable
scheduling through prose.

Once installed, this local workflow uses no live data service. A paper sheet or
locally saved CSV can be a later-import fallback. The actual editor/device must
save it; no durable mobile capture, automatic synchronization or multiuser offline
conflict resolution is claimed. Confirm local output only after the tool's successful
result; pending directories are not complete snapshots.

Keep farm originals under farmer control. An adviser copy is a new local directory,
not a sent message or accepted submission. Its omissions are explicit. Additional
sharing, external writes and professional decisions require their own authority
and evidence. Actual farmer, practitioner and French-user review remain open.

## Français

L’hôte exercé est Codex sous Windows, avec PowerShell local, CPython 3.14.3 et des
fichiers NTFS. L’agent lit explicitement les compétences de ce projet ; ce sont
des instructions portables du dépôt, pas une preuve de découverte automatique dans
un autre client. La roue Python fournit les commandes déterministes `capture`,
`reconcile`, `verify` et `handoff`. Le dépôt fournit les modèles bilingues et les
pièces du parcours.

L’opérateur ou l’hôte choisit les fichiers autorisés, enregistre réellement les
brouillons, vérifie les transcriptions et confirme le périmètre. Les drapeaux
consignent ces déclarations ; ils ne constituent ni une authentification, ni un
contrôle d’accès, ni une preuve de lecture du papier par le logiciel. Les permissions
du système et les limites d’accès de l’hôte continuent de s’appliquer. Seule la
lecture locale choisie est représentée ; aucun identifiant de compte n’est requis.
Une compétence ne fournit ni stockage, ni secrets, ni contrôle des rôles, ni
planification fiable par de simples instructions.

Après installation, ce parcours local n’utilise aucun service de données en direct.
Une feuille papier ou un CSV réellement enregistré localement peut servir à un
import ultérieur. L’éditeur ou l’appareil doit effectivement l’enregistrer ; aucune
saisie mobile durable, synchronisation automatique ou résolution de conflits hors
ligne entre utilisateurs n’est annoncée. Confirmez la sortie locale uniquement
après un résultat réussi de l’outil ; un dossier en attente n’est pas un instantané
validé.

Les originaux restent sous le contrôle de l’agriculteur. Une copie pour le conseiller
est un nouveau dossier local, pas un message envoyé ou un dépôt accepté. Ses
omissions sont explicites. Les partages supplémentaires, écritures externes et
décisions professionnelles exigent leur propre autorisation et leurs preuves.
Les révisions par des agriculteurs, praticiens et utilisateurs francophones restent
à effectuer.
